Deploy guide

Run your own Odysseus

From nothing to a bot that answers you in Telegram, first on your own computer and then on a small server that stays awake. These steps were followed for real, and where something went wrong, the page says so. They were run on Windows; the macOS and Linux forms shown beside them are the standard equivalents.

{{repo_notice}}

What you will need

Three accounts are required. Five more are optional, and each one switches on a capability. You can start with the three and add the rest later by adding a line to one file.

SettingWhere it comes fromWhat it is for
TELEGRAM_BOT_TOKENIn Telegram, message @BotFather and send /newbotThe bot you will talk toRequired
OWNER_TELEGRAM_IDYour own numeric Telegram ID; @userinfobot will tell youThe one account the bot answers. Everyone else is ignored.Required
ANTHROPIC_API_KEYThe Claude ConsoleThe model that does the thinkingRequired
EXA_API_KEYexa.aiWeb searchRequired
COMPOSIO_API_KEYThe Composio dashboardMail, calendar, and any other app you connect from the chatOptional
BROWSER_USE_API_KEYBrowser Use CloudThe browserOptional
MISTRAL_API_KEYThe Mistral consoleReading photos and PDFs you sendOptional
LANGFUSE_PUBLIC_KEY and LANGFUSE_SECRET_KEYA Langfuse project, with LANGFUSE_BASE_URL set to its regionA readable record of every task. Keys are removed, and mail text is replaced by its length.Optional

You also need Python 3.13 (the version it is tested on) and, for the server step, a card on a hosting account.

What it costs to run. The model and the other services bill you directly, by use. In single measurements made here a question with one web search cost about 1.5 cents and a browser run about 4 cents. The program enforces a limit per task (50 cents by default) and per day (3 dollars by default), and you can change both. A small server is a few dollars a month on top.

2

Fill in your keys

Copy the example settings file and put your values after each =.

macOS and Linux
cp .env.example .env
Windows (PowerShell)
Copy-Item .env.example .env

The file .env is ignored by git, is never put into the server image, and is never shown to the model. Fill in the four required lines. Leave the optional ones commented out until you want them.

Use your own numeric ID, exactly. OWNER_TELEGRAM_ID is the only thing that decides who the bot obeys. A message from any other account gets no reply at all and costs you nothing.

3

Start it and say hello

python -m odysseus

Open Telegram, find your bot by the username you gave BotFather, and send it a message. It should answer within a few seconds. Then try these:

SendWhat it does
stopEnds whatever it is doing. Handled by the program, never shown to the model.
/statusWhether it is busy, and what it has spent today
/memory and /forget a1b2See what it remembers about you, and remove an entry
/schedule and /cancel a1b2See reminders and routines, and cancel one
/appsWhether mail and calendar are connected, with a link for any that is not
/browser and /browser doneOpen its browser yourself to sign in to sites; then save the sign-ins

To connect mail and calendar, add COMPOSIO_API_KEY, restart, and send /apps. To connect any other app, just ask for work in it: the reply will carry a link.

Run only one copy. Telegram hands each message to one program. If two copies run with the same bot token, on your laptop and a server for instance, they take messages from each other. Stop one before starting the other.

4

Give it a server

On a laptop, reminders only fire while the laptop is awake. A small always-on server fixes that. These steps use Fly.io, which is what this project used; any host that can run a container with a persistent disk will do.

Add a payment card first. Skipping it cost two failed deployments. On a new Fly.io account with no card, every machine is stopped five minutes after it starts. Nothing in the deploy output says so. The bot starts, answers for five minutes and goes silent. The only trace is one line in the machine's log: "Trial machine stopping".

Create the app and its disk

Install the fly command from Fly.io, then:

fly auth login
fly apps create your-app-name
fly volumes create odysseus_data --app your-app-name --region sin --size 1

Open fly.toml and change three things: app to the name you just chose, primary_region to a region near you (fly platform regions lists them), and ODYSSEUS_TZ to your own time zone, for example Europe/London.

Do not skip the time zone. A server's clock is UTC. Without ODYSSEUS_TZ, "remind me at 7am" fires at 7am UTC, and nothing reports an error.

Send your keys as secrets

macOS and Linux
grep -E '^[A-Z_]+=.+' .env | fly secrets import --app your-app-name --stage
Windows (PowerShell)
Get-Content .env | Where-Object { $_ -match '^[A-Z_]+=.+' } | fly secrets import --app your-app-name --stage

Deploy

Stop the copy on your laptop first. Then:

fly deploy --ha=false

--ha=false matters: it asks for one machine. Two machines would be two copies of the bot.

Check that it stayed up

fly status
fly logs

You should see a line reading odysseus start, then one line per step as you use it: statuses and numbers, never the contents of your messages. Message the bot. Then check again after ten minutes. The first deployment was reported as working thirty seconds after launch, and it was switched off four and a half minutes later.

Optional: WhatsApp as a second channel

Telegram needs nothing to reach your server. WhatsApp does: Meta calls an address you own each time a message arrives. {{ch:channels}} of the book explains what that changes. This channel was built and tested without Meta and has not yet been connected, so treat these steps as untried.

  1. At developers.facebook.com, create an app and add the WhatsApp product. It gives you a test number, a phone number id, and under the app's basic settings an app secret. Create a permanent token for a system user with the two WhatsApp permissions.
  2. Add your own WhatsApp number as an allowed recipient of the test number.
  3. Set WHATSAPP_TOKEN, WHATSAPP_PHONE_ID, WHATSAPP_APP_SECRET, OWNER_WHATSAPP (your number with country code) and WHATSAPP_VERIFY_TOKEN (any phrase you choose) as secrets.
  4. Uncomment the [http_service] section at the end of fly.toml and deploy.
  5. In the Meta app, register the webhook address https://your-app-name.fly.dev/whatsapp with the same phrase, and subscribe to messages.

WhatsApp's 24-hour rule. The bot can write to you freely only for 24 hours after you last wrote to it. A reminder that falls outside that window is refused by WhatsApp. Reminders and routines are therefore sent on Telegram unless you set ODYSSEUS_NOTIFY_ON=whatsapp.

Updating later

Pull the new code and run fly deploy --ha=false again. Your memory, schedule and log live on the disk and are not touched by an update.

Settings worth knowing

All optional. Put them in .env locally, or set them with fly secrets set on a server.

SettingDefaultWhat it changes
ODYSSEUS_TASK_USD0.50The most one task may spend before it is ended
ODYSSEUS_DAILY_USD3.00The most one day may spend. After that, new tasks are refused until tomorrow.
ODYSSEUS_MAX_TURNS25The most steps one task may take
ODYSSEUS_MODELclaude-sonnet-5-5The model for conversations
ODYSSEUS_BACKGROUND_MODELclaude-haiku-5-5The model for unattended routines
ODYSSEUS_TZthe machine's clockYour time zone, for reminders and message times. Set it on any server.
ODYSSEUS_BROWSER_ASK_SIGNED_INonYou are asked before every browser run that is signed in as you. Set to 0 to let such runs start without asking

Think before turning that last one off. You are asked before a browser run signed in as you starts, but nothing asks before a click inside it. With the setting at 0 such a run starts without asking and is only reported afterwards. If you sign the browser in to anything that can spend money or speak for you, leave it on. What you are trusting

Running Odysseus yourself means nobody stands between you and your data except the services you choose to connect. Each one sees something:

ServiceWhat it sees
The model makerYour conversations, and whatever the tools return into them
The search serviceThe searches the model makes
The connector (optional)It holds the access to your mail, calendar and connected apps, and your mail passes through it
The browser vendor (optional)The tasks you browse, and the sign-ins you save there
The text-recognition service (optional)Every file you send the bot, in full
Your hostThe disk holding your memory, schedule and log

If something goes wrong

What you seeLikely cause
The bot answers for five minutes after a deploy, then nothingNo payment card on a new Fly.io account. Look for "Trial machine stopping" in fly logs.
No reply at all, and you are sure it is runningOWNER_TELEGRAM_ID is not your ID, or a second copy is running somewhere and taking the messages
"Missing settings: …" at start-upA required line in .env is empty. The message names which.
Reminders arrive hours offODYSSEUS_TZ is not set on the server
"Today's budget … is used up"The daily limit was reached. Raise ODYSSEUS_DAILY_USD or wait for tomorrow.
It says an app is not connectedOpen the link in its reply and approve, then tell it you have

To see what it actually did, read journal.jsonl in its data folder: one line per step, including every reply sent or lost. On Fly.io:

fly ssh console -C "tail -n 20 /data/journal.jsonl"

Checking your copy

The tests run in under a minute and call no outside service.

pip install -r requirements-dev.txt
pytest

They prove what the code around the model does. They do not prove that it works with real services; three faults in the first day were found only by running it for real. The scripts in scripts/ are the live checks used here, and each one spends a few cents.
