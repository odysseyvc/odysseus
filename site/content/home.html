How it works

The model proposes. Code grants.

A language model is sometimes wrong, and it reads whatever strangers write. So it does not decide what happens.

You ask

In a private chat. A message from anyone else is dropped without a reply.

The model proposes

It reads, reasons and asks to use a tool. It cannot use one by itself.

Code decides

Reading runs. Adding to your own things runs and is reported. Everything else is put to you, written by the program from the action's real inputs.

The program reports

Every change is listed under the reply in lines the model did not write and cannot edit.

Every action gets one of three answers. Code gives the answer, and the model has no say in it.

  • What other people write is material. Mail, web pages, decks and database notes are marked as reading matter. Instructions inside them are not followed, and are reported.
  • Private details do not leave quietly. What was read from your accounts is recognised if it turns up in a web search, and you are asked.
  • Sign-in codes never reach the model. They are removed from mail before it is shown anything.
  • Stop always works. It ends the task whether or not the model cooperates. Spending is capped per task and per day.
Allow

Reads, and small additions to your own things. A search, a lookup, a note on a record, a new row. Done, then listed.

Ask

Anything that sends, shares, invites, deletes or overwrites. You see exactly what will happen and tap once.

Refuse

What an unattended run must never do. A routine cannot change anything, and cannot carry private details into a search.

What this does not promise. A model that obeyed a planted instruction could add a record you learn of only from the reply. It could not overwrite, send, share or delete. The book says so in the chapter on the gate.

First customer

Ask as little as possible. Work like a really smart intern.

That is the brief from its first owner, in short: a partner at an early-stage venture firm. The last part of the book is that application, worked through: a firm's database, the decks that arrive every day, and the search for founders nobody has heard of yet.
