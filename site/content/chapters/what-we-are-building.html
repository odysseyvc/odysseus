After this chapter you should be able to
  • State the goal of Odysseus in one sentence and say what is deliberately left out of the first version.
  • Distinguish a chatbot from an agent, and a tool from a connector.
  • Explain why "the agent said it was done" is not evidence, and define trusted completion.
  • Say why Telegram was chosen as the first channel and what that choice costs.

The goal

Odysseus is a personal AI agent for one person. You send it a message in Telegram; it works out what has to be done, does it using your mail, your calendar, the web and a browser, and comes back either with the result or with a question. Before it sends, pays, deletes or shares anything, it asks.

That sentence hides most of the difficulty. "Works out what has to be done" means a language model choosing actions in a loop. "Using your mail" means holding the keys to accounts that matter. "Asks before" means that some part of the system which is not the model must be able to stop the model. The rest of this book takes those three clauses apart.

The name is the owner's choice. Odysseus got home by being resourceful and by having himself tied to the mast when he knew his own judgement would fail. Chapter 3 is about the mast.

The project starts from zero. Its owner has built assistants before, and none of that code and none of its assumptions are carried over. The reason is practical: a design inherited from an earlier attempt is hard to question, and the point of this book is to question each choice in the open.

Vocabulary

Seven words carry most of the meaning in what follows. They are used loosely elsewhere and exactly here.

Definitions
Chatbot
A program that answers messages with text. It changes nothing in the world except what is on your screen.
Agent
A program in which a language model repeatedly chooses an action, sees the result and chooses again, until the task is finished or it gives up. The repetition is called the agent loop.
Tool
One action the model may choose: search the web, read a file, click a button, send an email. The model does not perform the action. It writes a request; ordinary code performs it and hands back the result.
Connector
A set of tools that reach one outside service, such as a mail account, through that service's official interface.
Channel
The place the conversation happens. For Odysseus this is a private Telegram chat.
Approval gate
Code that intercepts an action with consequences, shows the person exactly what is about to happen, and carries it out only after they agree.
Routine
A task the agent starts by itself on a schedule or when something happens, without a message from the person.

The definition of a tool contains the most useful fact in the book. Because the model only asks for actions and code carries them out, there is always a point between the asking and the doing where a rule can be enforced. Every safety measure in later chapters lives at that point.

Worked example: one request, traced

The message is: "Find a time next week for lunch with Priya and send her an invite."

  1. The model asks for the calendar.list tool for next week. Code runs it and returns the busy times.
  2. The model picks Wednesday 12:30 and asks for calendar.create with Priya as a guest.
  3. Creating an event with a guest sends her an email. That is an action with a consequence, so the approval gate holds it and posts in the chat: "Create 'Lunch', Wed 12:30 to 13:30, and invite priya@example.com? [Yes] [No]". The text is assembled by code from the tool's actual inputs, not written by the model.
  4. You tap Yes. Code creates the event and returns the result to the model, which replies that it is done.

Steps 1 and 2 are the agent loop. Step 3 is the gate. A chatbot would have stopped before step 1 and told you how to do it yourself.

Why Telegram first

The channel was the owner's decision, and the research in Chapter 2 turned up a fact that makes it more interesting: none of the three reference products is offered in Telegram. Secondary Instinct runs on iMessage, WhatsApp, phone calls and email. Muse runs in Meta's own apps and WhatsApp. Grok Bot runs in its own apps, Slack and email. The official Grok account on Telegram is a separate product from 2025 that answers questions and does nothing else.

Telegram suits the job for technical reasons too. Verified Its Bot API (version 10.4, 9 November 2026) lets a bot stream a reply as it is written, attach buttons to a message, receive files and voice notes, and split a private chat into topics. A bot can also collect its messages by asking Telegram for them repeatedly, which is called long polling, so the server needs no public web address.

The cost of the choice is reach. A Telegram bot cannot text someone who has not started a chat with it, cannot place a phone call, and has no email address of its own. Those are things Instinct does. They are left out of the first version on purpose.

What counts as working

An agent that finishes a task says so. An agent that fails a task quite often says so too, in the same confident words. The model's own report is therefore not a measurement.

Definitions
Task completion
The share of tasks whose outcome is correct when checked by something other than the agent: a person, a second system, or the state of the account afterwards.
Trusted completion
The share of tasks that were completed and in which the agent stayed inside the person's rules: it asked where it should have asked, touched nothing it was not meant to, and leaked nothing.

Trusted completion is the measure this project will report. It is the stricter of the two, and it is the one the reference products have had trouble with (Chapter 2).

How high is the bar? One public test exists. A company called micro1 gave 20 tasks to six assistants and had experts mark each attempt. Secondary Our research read the results as 65% trusted completion for Instinct and for Grok Bot, 55% for Muse and 80% for the best assistant tested. Two cautions apply. The authors themselves describe the sample as small and the ranking as not definitive. And accounts of the results disagree with one another about which assistants were tested and which came first, so we do not yet treat 65% as a firm target.

Caution

Odysseus has no score of its own. It will have one when Chapter 14 is written, from tasks the owner really needs done. Until then, any sentence that says Odysseus is as good as, or better than, another product would be false, and none appears on this site.

What is left out, for now

The first version will not make payments, place phone calls, join group chats or act inside the owner's conversations with other people. Each of these is something a reference product does, and each adds a way to cause harm that the simpler system does not have. They wait until the simpler system has a stable score.

Summary
  • Odysseus is an agent, not a chatbot: a model chooses actions in a loop and code carries them out.
  • Because code carries out every action, code can refuse or pause any action. That is where safety is built.
  • Success is measured as trusted completion, checked by something other than the agent.
  • Telegram is the first channel. None of the three reference products is there.
Check your understanding
  1. A program reads your inbox every morning and sends you a summary, with no model involved in deciding what to do. Is it an agent by this chapter's definition?
    Answer

    No. It runs a fixed sequence. An agent has a model choosing the next action from the result of the last. It is, however, a routine, and Odysseus will contain fixed routines like it where no judgement is needed.

  2. In the worked example, why must the approval text be assembled by code and not written by the model?
    Answer

    If the model writes the text, a model that has been misled can describe one action and request another. Text built from the tool's real inputs cannot differ from what will be executed.

  3. An assistant completes 18 of 20 tasks but, in 5 of those, emails someone without asking. What are its task completion and trusted completion?
    Answer

    Task completion is 18 of 20, or 90%. Trusted completion is 13 of 20, or 65%.
