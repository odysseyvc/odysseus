Why a second channel is cheap, and where it is not

Chapter 6 kept all decisions in one place and gave the channel a deliberately small job: carry text out, show a draft, and ask a question with two buttons. Telegram was the only thing that did that job. The owner asked for WhatsApp as well.

Because of that early separation, nothing about who may speak, what a "stop" does, the gate, memory or the schedule had to change. A WhatsApp message from the owner reaches the same conversation code as a Telegram one. The new file is about 170 lines and contains no decisions.

What did change is the shape of the connection, and that has consequences for safety.

A channel that calls you needs a door

Definitions
Polling
The program asks the service "anything new?" over a connection it opened itself. Telegram works this way here. Nothing on the internet can start a conversation with the program.
Webhook
The service calls an address the program owns whenever something happens. WhatsApp works only this way. The program must listen at an address the internet can reach.
Signature
A value sent with a message that could only have been computed by someone holding a shared secret. It proves who sent the message and that it was not altered.

Chapter 13 was able to say that the server "opens no port to the internet", and that a server with no door needs no guard. WhatsApp ends that. With this channel switched on, the program listens on a port, and anyone who finds the address can send it anything.

So three checks stand at the door, and a delivery must pass all three before any of it is acted on.

The three checks, in the order they are applied.
CheckWhat is checkedWhat it stops
The handshakeWhen the address is registered, Meta sends back a phrase the owner chose. It must match.Someone else registering the owner's address as theirs
The signatureEvery delivery carries a signature computed from its exact bytes and the app's secret. The program computes it again and compares.Anyone but Meta sending a delivery, and any change to one on the way
The senderThe number the message came from must be the owner's.Any other WhatsApp user who messages the bot's number

A delivery that fails the signature is dropped without being read. A message from another number gets no reply at all, as with Telegram, so that a stranger cannot even learn that something is there.

Meta's documentation calls checking the signature "optional but recommended". For a program that can send mail from its owner's account, it is not optional.

Two smaller points follow from the same shape. Meta retries a delivery for up to 36 hours if it is not acknowledged, so the same message can arrive twice; the program remembers recent message ids and handles each once. And Meta expects an answer at once, so the delivery is acknowledged immediately and the work is done afterwards.

The 24-hour rule

WhatsApp allows a business number to send ordinary messages to a person only for 24 hours after that person last wrote. Each message from the person restarts the clock. Outside that window, only a pre-approved template may be sent, and those are charged per message. Verified in Meta's documentation, November 2026.

For a program that only answers, this rule is invisible. For an assistant that speaks first (Chapter 8), it is a real limit: a reminder set on Monday for Thursday falls outside the window unless the owner happens to have written since Wednesday.

Templates are not built here. So the honest state is this: on WhatsApp, a reminder or routine is delivered if the owner has written in the last 24 hours and is refused by WhatsApp otherwise. By default reminders and routines are sent on Telegram, where no such rule applies. A setting sends them to WhatsApp instead.

Corrected

This paragraph used to say the refusal was "logged, never silent". For the owner it was silent: a one-off reminder that WhatsApp refused was written to the log, deleted, and never sent anywhere. A log line nobody reads is silence. Now a message that WhatsApp refuses is sent on Telegram instead, and a reminder that cannot be sent on any channel is kept and tried again after 1, 5, 15 and 30 minutes before it is recorded as failed (Chapter 20). Verified by unit tests with a channel that refuses; not yet seen against the real WhatsApp.

Approval, on a different screen

The gate's rule from Chapter 9 is that only a button counts as approval, and that the owner must have been shown everything the button covers. WhatsApp has reply buttons, with a limit: a button message holds 1,024 characters, a quarter of what Telegram allows.

An approval question longer than that is sent as ordinary messages first, with the two buttons on the last part. The buttons carry only the approval's id; what will run is held by the gate, as before. A typed "yes" on WhatsApp is an ordinary message, as it is on Telegram.

Chapter 15's research recorded users of one commercial assistant reporting WhatsApp bans. Secondary The first route was chosen. The cost is the set-up, and the 24-hour rule comes with it.

What connecting it took

The code was an afternoon. The set-up at Meta took longer, and none of it could be done by a program acting alone. In order: a Facebook account; registration as a developer, with a code sent to a phone; a "business portfolio", which a new account was made to wait an hour before creating; an app, whose creation asked for the account's password again; acceptance of WhatsApp's own business terms; a test number; a token, issued through a pop-up window that only a person's click may open; the app's secret, shown only after the password a third time; and the owner's own number added as a permitted recipient, confirmed by a code sent to WhatsApp.

Three things are worth knowing before starting.

  • The first message cannot be an ordinary one. Until the owner has written to the bot's number, only a pre-approved template may be sent. Meta provides a sample for the purpose. After the owner replies, the 24-hour window is open and the bot's own messages go through.
  • The token from the set-up page lasts about two hours. It is for trying things out. A bot that is meant to keep running needs a long-lived token, made for a "system user" in the business's settings.
  • A test number can write to five phone numbers, each of which must be added and confirmed by hand. For an assistant with one owner that is no limit at all.

Summary
  • Keeping every decision out of the channel made a second channel a small file.
  • A channel that calls the program needs an address the internet can reach. That is a door, and it needs guarding.
  • Three checks: the handshake, the signature on every delivery, and the sender's number.
  • WhatsApp lets a business number write freely only for 24 hours after the person last wrote. An assistant that speaks first runs into this.
  • Use the platform's own interface. Imitating the phone app risks the owner's own number.
Check your understanding
  1. The signature check is removed "to make testing easier" and never put back. Describe an attack.
    Answer

    Anyone who learns the address sends a delivery shaped like a WhatsApp message, with the owner's number in the "from" field. The sender check passes, because the number is whatever the attacker wrote. The program now takes instructions from a stranger as if they were the owner's. The signature is what makes the "from" field believable.

  2. The owner sets a reminder on Monday for Thursday at 9am and chooses to receive reminders on WhatsApp. They last wrote on Tuesday. What happens on Thursday?
    Answer

    The 24-hour window closed on Wednesday. WhatsApp refuses the message. The program logs the refusal and the reminder is recorded as failed. Nothing arrives on WhatsApp. This is why reminders go to Telegram unless the owner chooses otherwise.

  3. Why is a delivery acknowledged before it is handled, and what does that make necessary?
    Answer

    Meta expects a quick answer and retries when it does not get one; a task can take a minute. Acknowledging first avoids retries of slow tasks. But a retry can still happen if the acknowledgement is lost, so the program must recognise a message it has already seen and not act on it twice.
